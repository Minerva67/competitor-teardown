# competitor-teardown：拆一个竞品，每个结论都标明证据来源

多数竞品分析只看了官网，然后把营销文案当成产品事实写进报告。官网展示的是对方希望你相信的样子：它会落后于产品、夸大规格，有时和产品里的实际做法正好相反。

这个 skill 分三层取证，每个结论都标注来自哪一层。你能分清哪些可以直接用来做决策，哪些还需要再验证。

## 适合什么时候用

- 拆解一个产品，看看这家竞品是怎么做的
- 想知道对方的定价实际怎么算、付费墙设在哪里
- 要决定自己做不做某个功能，先看看别人做成什么样
- 要给老板或团队交一份竞品报告

## 三层证据

| 层 | 看什么 | 需要你提供 |
|---|---|---|
| 公开信息 | 官网、定价页、落地页和博客、融资与团队、第三方评价 | 不需要 |
| 登录后台 | 实际的功能结构、每个选项、付费墙位置、应用内定价 | 你自己登录 |
| 实际使用 | 扣费方式、生成耗时、产出质量、背后用了哪些供应商 | 你同意花额度或付费 |

能做到哪一层就做到哪一层。没做到的部分会写进「未覆盖」清单，并说明验证它需要什么。如果进入后台或实测后推翻了之前根据官网得出的结论，报告开头会单独列出更正：原来以为是什么，实际是什么。

## 你会拿到什么

一份 HTML 报告，包括：

- 更正：营销信息和实际产品不一致的地方
- 定位、定价、功能、增长打法的拆解，每条标注「原文」「推断」或「实测」
- 后台界面截图
- 对你自己产品的行动清单
- 未覆盖清单

如果你之前拆过同类产品，把那份报告一起给它，它会逐项对照。

## 需要注意

- 它不会替你注册账号、输入密码或付款。需要登录时会打开页面，请你自己操作。
- 会消耗额度或产生费用的操作都会先问你，说明花多少、要验证什么。
- 登录后台和截图需要 Claude 桌面版 Code 标签页里的内置浏览器。只看公开信息时不需要。

## 怎么用

- 「拆解一下 xxx.com」
- 「他们凭什么收这么贵」
- 「对标一下我们，看看他们后台长什么样」

## 包含的文件

- `SKILL.md`：四个阶段的流程和规则
- `references/report-structure.md`：报告章节和每节写法
- `references/evidence-playbook.md`：每层看什么、怎么取、什么算可靠证据
- `scripts/screenshot-pipeline.js`：把后台界面截图保存成文件的代码
